# 从 426 条人工标注推导判定规则

> 本文只包含聚合统计与结论，**不含任何用户昵称、UID 或评论原文**。原始数据与标注文件因隐私原因不随仓库提供，`samples/fetch-real-comments.mjs` 可自行复现。

## 1. 为什么不用仿真数据调参

前两版规则是在自建样本上调的，误报率 0，一上真实页面就翻车两次：

- 第一次：把「讨论 AI 冒充」的真人整页标成 AI —— 因为视频本身在讲这个主题，所有真人都在说 `Claude` / `token` / `冒充`；
- 第二次：把「多个账号讨论同一组术语」当成 AI 读字幕的指纹 —— 但这恰恰是真人围着一个技术视频讨论的正常表现。

两次的共同原因是**负样本盲区**：自建样本里的真人只有「钓鱼打窝玩梗」，被硬保护兜住了，从没构造过「一群高等级老号正经讨论同一个技术视频」。

所以改成：直接导出一页真实评论区，逐条人工标注，用标注推导规则。

## 2. 数据集

| 项目 | 数值 |
|---|---|
| 视频 | 一个讨论「AI 中转站 / 模型冒充」的视频 |
| 导出方式 | B 站公开评论接口（无需登录），热门分页 + 最新分页 + 楼中楼 |
| 请求数 | 36 次 |
| 评论条数 | 504（266 主评论 + 238 楼中楼） |
| 账号数 | 426 |
| 有签名账号 | 229 / 426 |

标注是对话式分 13 批完成的（每批 20~60 个账号），工具见 `samples/real/label.mjs`。

### 标签定义

| 标签 | 含义 | 期望处置 | 数量 |
|---|---|---|---:|
| `a` | AI 自动发评账号 | 隐藏 | 42 |
| `d` | 带外链的广告号 | 隐藏 | 6 |
| `s` | 人机共用（高等级 + 签名自述） | 只标记 | 10 |
| `h` | 真人 | 保留 | 349 |
| `m` | 真人玩梗 / 钓鱼打窝 | 保留 | 19 |

隐藏类 48、标记类 10、保留类 368。

## 3. 数据推翻的四个假设

| 假设 | 实际情况 | 后果 |
|---|---|---|
| 头像聚类是决定性特征 | 公开 API 的 `member.face` **全部为空（0/426）** | 头像只能用 DOM `img` 兜底，降级为可选佐证 |
| 高等级老号 = 真人 | 签名里出现「本账号由…运营」「不定时由…接管」「共享账号」 | 需要区分「人机共用」，只标记不隐藏 |
| 文本出现 AI 主题词 = AI | 视频主题就是 AI 冒充，真人全在聊这些 | 主题词**整体作废**，不能作为证据 |
| 跨账号文本雷同 = AI 模板 | 同一个打窝句式被 6 个不同账号一字不差复读，全是真人玩梗 | 雷同不能单独定罪 |

## 4. 等级是最强的分界线

| 等级 | `a` 隐藏 | `s` 标记 | `h` 真人 | `m` 玩梗 | `d` 广告 |
|---|---:|---:|---:|---:|---:|
| Lv2–3（77 个） | 40 | 5 | 24 | 2 | 6 |
| Lv4–6（349 个） | 2 | 5 | 325 | 17 | 0 |

Lv4+ 里 99.4% 是真人。这一条比任何文本特征都强。

## 5. 各标签的特征命中率

| 标签 | 核心人设昵称 | 含弱人设字 | 签名自述 AI | 人设口癖 | 对主人说话 | 打窝复读 | 外链广告 | 短评 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `a`（42） | 48% | 71% | 14% | 50% | **5%** | 2% | 0% | 31% |
| `s`（10） | 40% | 60% | **100%** | 30% | 0% | 0% | 0% | 30% |
| `h`（349） | 4% | 8% | 0% | 5% | 0% | 0% | 0% | **76%** |
| `m`（19） | 5% | 16% | 0% | 11% | 5% | **100%** | 0% | 32% |
| `d`（6） | 0% | 0% | 0% | 0% | 0% | 0% | **83%** | 50% |

**关键发现：`对主人说话` 在 `a` 类里只占 5%。**

第二版规则把它当成隐藏的必要条件，导致在这批真实标签上召回只有 **10.4%**（48 个该隐藏的漏了 43 个）—— 精确率 100%，等于没干活。

## 6. 候选规则对比

评估口径：隐藏类 = `a` + `d`，保留类 = `h` + `m`，标记类 = `s`。

| 规则 | 正确隐藏 | 误藏 | 漏判 | 精确率 | 召回率 | F1 |
|---|---:|---:|---:|---:|---:|---:|
| v2：签名自述 + 对主人说话 | 5 | 0 | 43 | 1.000 | **0.104** | 0.189 |
| R1：低等级 + 任一身份信号 | 42 | 14 | 6 | 0.750 | 0.875 | 0.808 |
| R5：R1 + 排除打窝 / 短评真人口语 | 41 | 13 | 7 | 0.759 | 0.854 | 0.804 |
| R6：R5 + 低等级签名自述只标记 | 40 | 11 | 8 | 0.784 | 0.833 | 0.808 |

最终实现取 R6 的结构（闸门式），并在真实页面上补充了「打窝保护只给非人设昵称」等修正。

## 7. 最终规则（闸门式，按顺序短路）

```
1  白名单 / 屏蔽名单 / 单条人工处置        → 按用户
2  含外链推广                              → 隐藏
3  真人硬保护（打窝复读 / 笑声 / 自证 /
   社区打卡短句 / 短评+具体口语）           → 保留
   例外：顶着核心人设昵称复读打窝          → 不保护
4  Lv4+ 且签名自述 AI / 核心人设昵称       → 只标记
5  Lv4+ 且无人设                          → 保留
6  Lv≤3 且只有模糊签名自述、无其它信号     → 只标记
7  Lv≤3 且命中身份信号（核心/弱人设昵称、
   签名自述、人设口癖、对主人说话）         → 隐藏
8  其余                                    → 保留
```

页面级统计（同族人设昵称规模、签名族、共享主题词、互 @ 链、时间聚集、DOM 头像簇）**只用于展示判定依据与模型输入，不单独构成证据**。

## 8. 真实标注集上的最终表现（纯规则）

| 指标 | 值 |
|---|---:|
| 正确隐藏 TP | 42 |
| 误藏 FP | 13 |
| 漏判 FN | 6 |
| 精确率 | 0.764 |
| 召回率 | 0.875 |
| F1 | 0.816 |
| 426 个账号推理耗时 | 约 100 ms |

误差来源：13 个误藏里约 4 个是「人机共用」被过度隐藏、其余多来自标注本身的不一致（同一类「鱼系昵称 + 低等级」在批次前半标 `a`、后半留默认 `h`）。这部分已整理为待复核清单，是本项目当前精度的主要上限。

## 9. 复现

```bash
npm install
npm run fetch:real -- 12    # 导出你自己机器上的真实评论（数据只落在本地）
npm run analyze:real        # 聚类分析，生成待标注清单
node samples/real/label.mjs 1 "同意"   # 对话式逐批标注，结果写 labels.json
npm run eval:real           # 用你的标注评估规则
npm run analyze:real        # 交叉表 + 各标签特征命中率 + 规则对比
```

`label.mjs` 支持「同意」采用默认、`3a 7h` 局部改、整串字母覆盖、`全部h` 批量，适合边看边标。
